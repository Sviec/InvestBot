# InvestBot

Телеграм-бот для анализа публичных компаний: отчётность, мультипликаторы,
графики котировок, технические индикаторы, обзоры секторов и отраслей,
портфель, избранное и персональная статистика. Данные берутся из Yahoo Finance
через `yfinance`, справочники компаний, секторов и отраслей хранятся в
PostgreSQL.

## Возможности

- **Анализ компании** — справка, описание, дивиденды, мультипликаторы, ключевые
  показатели (маржи, рост, FCF, целевые цены), новости, график котировок за
  произвольный период, финансовая и балансовая отчётность, денежный поток,
  отчёт о прибыли, состав держателей акций, технические индикаторы
  (MA, RSI, MACD, Momentum, OBV).
- **Анализ сектора и отрасли** — обзор, топ компаний, топ ETF, отрасли сектора
  с рыночным весом, динамика ведущего ETF, топы отрасли таблицей и диаграммой.
- **Избранное** — список компаний пользователя с быстрым переходом в карточку.
- **Портфель** — журнал сделок, позиции методом средней стоимости, сводка с
  рыночной стоимостью и нереализованным P&L, история; сделку можно добавить
  из карточки компании.
- **Статистика** — персональная сводка: оценка портфеля, лучшие/худшие позиции,
  оценка дивидендов, распределение по секторам, активность в боте.
- **Справка** — ссылки на материалы по мультипликаторам и техническому анализу.

Прогнозирование отмечено в интерфейсе как раздел в разработке: навигация до
выбора компании работает, сам прогноз не считается.

## Требования

- Python 3.12
- PostgreSQL 13 и новее

Отдельного Redis или иного внешнего кеша не нужно: FSM — `MemoryStorage` в
памяти процесса, рыночный кеш и троттлинг — свои `TTLCache`.

## Установка

```bash
python -m venv venv
venv\Scripts\activate        # Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env       # Linux/macOS: cp .env.example .env
```

Заполните `.env`: как минимум `BOT_TOKEN` и параметры подключения к БД.
Полный список переменных с пояснениями — в `.env.example`.

## Миграции

Схема базы управляется Alembic.

**Новая база:**

```bash
alembic upgrade head
```

**Существующая база с данными.** Ревизия `0001_initial` описывает схему,
которая была до введения миграций, поэтому её нужно отметить выполненной,
а затем применить обновление:

```bash
alembic stamp 0001_initial
alembic upgrade head
```

Ревизии применяются подряд одной командой `upgrade head`:

- `0002_hardening` — приведение схемы в рабочее состояние (см. ниже);
- `0003_dedup` — удаление дублирующих внешних ключей и уникальных ограничений,
  накопившихся до введения миграций, и снятие уникальности с `user.username`:
  Telegram освобождает username при отказе от него, и повторно занятое имя
  ломало бы регистрацию нового пользователя;
- `0004_username_nullable` — `user.username` становится необязательным, так как
  у пользователя Telegram может не быть имени;
- `0005_portfolio` — журнал сделок `portfolio_transaction` для учёта портфеля
  (позиции считаются агрегацией методом средней стоимости, не хранятся отдельно);
- `0006_user_events` — журнал действий `user_event` для личной статистики
  (просмотры экранов пишутся асинхронно пачками, без задержки ответа).

Ревизия `0002_hardening` переводит `user.telegram_user_id` в `BIGINT`,
чистит дубликаты в `favourites` и добавляет внешние ключи и индексы. Перед
созданием внешних ключей она обнуляет ссылки `company` на несуществующие
справочники и удаляет записи `favourites` с битыми ссылками, сообщая об этом
в вывод. Если в `industry` есть строки с несуществующим сектором, внешний ключ
не создаётся: данные нужно починить вручную.

Справочники `sector`, `industry` и `company` наполняются извне — бот их только
читает.

### Права на выполнение миграций

Роль из `DB_USER` — рантайм-роль бота, ей достаточно `SELECT`, `INSERT`,
`UPDATE` и `DELETE`; владельцем таблиц она быть не должна. Миграции меняют
схему, поэтому запускаются от владельца таблиц. Alembic берёт подключение из
тех же переменных окружения, а они имеют приоритет над `.env`, так что
достаточно переопределить их на время команды:

```powershell
# PowerShell
$env:DB_USER="postgres"; $env:DB_PASSWORD="<пароль>"
python -m alembic upgrade head
Remove-Item Env:DB_USER, Env:DB_PASSWORD
```

```bash
# Linux/macOS
DB_USER=postgres DB_PASSWORD='<пароль>' alembic upgrade head
```

Если роли не хватает прав, PostgreSQL сообщает `нужно быть владельцем таблицы`,
и Alembic откатывает ревизию целиком — схема остаётся в прежнем состоянии.

## Запуск

```bash
python main.py
```

Перед началом опроса Telegram бот проверяет конфигурацию, дерево меню,
соединение с БД и токен. При любой неудаче он завершается с понятным
сообщением и кодом возврата (`78` — ошибка конфигурации, `69` — недоступна
зависимость), а не падает позже на действии пользователя.

## Развёртывание на Ubuntu (Docker Compose)

Основной способ запуска на сервере — контейнеры: бот (long polling) и
PostgreSQL. Входящие порты не нужны; с сервера должен быть исходящий HTTPS к
`api.telegram.org` и к Yahoo Finance (при блокировке региона — `MARKET_PROXY`
в `.env`). Одновременно должен работать **один** экземпляр бота: FSM хранится
в памяти процесса.

### 1. Установить Docker

На Ubuntu 24.04 / 26.04 — Docker Engine и плагин Compose по
[официальной инструкции](https://docs.docker.com/engine/install/ubuntu/).
Кратко:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker "$USER"
```

После `usermod` перелогиньтесь, чтобы группа `docker` применилась.

### 2. Код и `.env`

```bash
sudo mkdir -p /opt/investbot
sudo chown "$USER":"$USER" /opt/investbot
git clone <url-репозитория> /opt/investbot
cd /opt/investbot
cp .env.example .env
chmod 600 .env
```

В `.env` обязательно задайте:

- `BOT_TOKEN` — токен от BotFather;
- `DB_PASSWORD` — пароль рантайм-роли бота;
- `POSTGRES_PASSWORD` — пароль владельца БД (миграции);
- при необходимости `MARKET_PROXY`, если Yahoo недоступен из региона сервера.

`DB_HOST` в Compose перекрывается на `postgres` (имя сервиса). Роли
`DB_USER` и `POSTGRES_USER` должны различаться: бот не должен быть владельцем
таблиц (см. «Права на выполнение миграций» выше).

### 3. Поднять PostgreSQL и применить миграции

```bash
docker compose up -d postgres
docker compose ps   # postgres — healthy
```

При первом создании тома скрипт `docker/postgres/init.sh` создаёт рантайм-роль
и `DEFAULT PRIVILEGES` на будущие таблицы.

Миграции — от владельца (переменные окружения перекрывают `.env`):

```bash
docker compose run --rm \
  -e DB_USER="${POSTGRES_USER:-investbot_owner}" \
  -e DB_PASSWORD="${POSTGRES_PASSWORD}" \
  bot alembic upgrade head
```

Если таблицы уже были созданы без прав для рантайм-роли, один раз выполните
`docker/postgres/grant_runtime.sql` от владельца (подставьте имя из `DB_USER`,
если оно не `investbot`):

```bash
docker compose exec -T postgres \
  psql -U "${POSTGRES_USER:-investbot_owner}" -d "${DB_NAME:-investbot}" \
  < docker/postgres/grant_runtime.sql
```

### 4. Справочники

Таблицы `sector`, `industry` и `company` бот только читает. Загрузите их
своим дампом или скриптом **до** проверки разделов анализа в Telegram, иначе
карточки компаний и обзоры секторов будут пустыми или с ошибкой «не найдено».

### 5. Запустить бота

```bash
docker compose up -d --build
docker compose logs -f bot
```

В логе должны появиться проверка БД и строка вида `Запускаюсь как @...`.
Коды выхода те же, что у `python main.py`: `78` — конфигурация, `69` —
зависимость (нет БД и т.п.).

Smoke-проверка: `/start` в Telegram, открытие карточки компании (нужны
справочник и доступ к Yahoo).

Полезные команды:

```bash
docker compose ps
docker compose logs -f bot
docker compose restart bot
docker compose down          # остановить; том pgdata сохранится
```

### 6. Обновление на сервере

```bash
cd /opt/investbot
git pull
docker compose build bot
docker compose run --rm \
  -e DB_USER="${POSTGRES_USER:-investbot_owner}" \
  -e DB_PASSWORD="${POSTGRES_PASSWORD}" \
  bot alembic upgrade head
docker compose up -d
```

### Тексты интерфейса

Пользовательские строки лежат во внешних JSON, а не в Python:

- `app/data/menu/{lang}.json` — дерево меню: тексты экранов, подписи кнопок,
  подсказки ввода (`input_text`);
- `app/data/messages/{lang}.json` — остальные сообщения (welcome, ошибки,
  прогресс, подписи отчётов и статистики).

В коде строка берётся через `app.utils.i18n.t("ключ", **плейсхолдеры)`. Язык
задаётся `BOT_LANGUAGE`; пустой или отсутствующий файл (как `en.json`)
откатывается на `ru`. Меню и каталог сообщений не смешиваются: ключи меню —
это сегменты пути навигации, ключи сообщений — плоские идентификаторы вроде
`handlers.portfolio.empty_positions`.

### Навигация

Состояние экрана целиком закодировано в `callback_data` — путь вида
`company%AAPL#tckr%c_fa%fa_fin%fin_quarter`. Сегменты с решёткой
(`AAPL#tckr`, `12#sctr`, `2#pg`) — подставленные значения: тикер,
идентификатор справочника, номер страницы. Хранилище для навигации не нужно,
поэтому кнопки продолжают работать после перезапуска бота.

Telegram ограничивает `callback_data` 64 байтами, а читаемый путь в этот лимит
не помещается. Перед отправкой путь сжимается: имена узлов заменяются
четырёхсимвольными псевдонимами (`app/utils/path_codec.py`). Псевдоним
считается от хеша имени, а не от порядкового номера, поэтому добавление пункта
меню не ломает кнопки в уже отправленных сообщениях. Кнопка с неизвестным
псевдонимом попадает в обработчик устаревших сообщений и открывает главное меню.

### Асинхронность

Обращения к PostgreSQL (psycopg2), к yfinance и отрисовка matplotlib —
синхронные. Все они выполняются через `app/core/executor.run_blocking` в пуле
потоков с таймаутом, поэтому долгий запрос одного пользователя не блокирует
обработку остальных. Размер пула задаётся `WORKER_THREADS`, число одновременных
отрисовок — `RENDER_CONCURRENCY`, одновременных рыночных запросов —
`MARKET_CONCURRENCY`.

### Отказоустойчивость

- Сессия к Yahoo создаётся с TLS/HTTP-отпечатком браузера
  (`MARKET_IMPERSONATE`, по умолчанию `chrome`). Без него провайдер отвечает
  `429`, и повторы съедают весь `MARKET_TIMEOUT`.
- Ответы провайдера кешируются по ярусам (отчётность — сутки, info — 30 мин,
  короткие котировки — 15 мин, длинные — 6 ч и т.д., см. `.env.example`);
  при сетевой ошибке запрос повторяется с экспоненциальной задержкой, а если
  источник недоступен совсем — отдаются последние известные данные в пределах
  `MARKET_CACHE_STALE_TTL`.
- Повторы ограничены общим бюджетом времени, равным `MARKET_TIMEOUT`. Без него
  зависший провайдер держал бы рабочий поток ещё долго после того, как ответ
  пользователю уже отправлен, и пул потоков исчерпывался бы. Бюджет обязан
  покрывать все запланированные попытки вместе с пробой тикера, иначе ожидание
  оборвётся раньше, чем выяснится причина отказа, и пользователь увидит
  сообщение о таймауте вместо недоступности источника. Соотношение
  `MARKET_TIMEOUT`, `MARKET_HTTP_TIMEOUT` и `MARKET_RETRY_ATTEMPTS` проверяется
  на старте.
- Одновременных рыночных запросов не больше `MARKET_CONCURRENCY`, что меньше
  `WORKER_THREADS`. Недоступный провайдер поэтому не занимает весь пул, и
  разделы, работающие только с БД, продолжают отвечать.
- Несуществующий тикер кешируется как отрицательный результат и не создаёт
  повторных обращений к провайдеру. Вывод о том, что тикера нет, делается не по
  пустому ответу — так же выглядит и сбой, — а по прямому ответу провайдера
  «не найдено». Хранится такой результат `MARKET_NEGATIVE_TTL` секунд, чтобы
  ошибочный вывод не пережил кратковременный сбой.
- Пустой ответ разбирается на три случая одним запросом к chart-эндпоинту:
  тикера нет, бумага есть (котировки отдаются, а профиля у провайдера просто
  нет) и провайдер не ответил внятно. Второй случай не выдаётся за недоступность
  источника: карточка открывается, работают графики и отчёты. Третий не
  повторяется — провайдер уже опрошен, повтор удвоил бы ожидание, не добавив
  сведений, и в кеше он не оседает.
- Запрос к БД повторяется при обрыве соединения; пул использует `pool_pre_ping`.
- Ошибки хендлеров перехватываются middleware и превращаются в понятное
  пользователю сообщение; технические подробности уходят в лог.
- Действия пользователя пишутся в `user_event` через очередь фиксированного
  размера: хендлер не ждёт INSERT. Пачка уходит в БД по размеру или по
  таймауту (`EVENTS_BATCH_SIZE` / `EVENTS_FLUSH_INTERVAL`); при переполнении
  очереди события отбрасываются. Старые записи чистятся при старте
  (`EVENTS_RETENTION_DAYS`).

### Логи

Пишутся в консоль и в `logs/bot.log` с ротацией. Каждая строка содержит
идентификатор пользователя и апдейта, включая записи из слоя данных.
Уровень задаётся `LOG_LEVEL`. Обёртки `db_call` / `market_call` / `render_call`
пишут длительность каждой стадии: дольше секунды — на INFO, быстрее — на DEBUG.
Апдейт дольше 1.5 с помечается предупреждением с типом события и, для
callback-кнопок, узлом меню.

## Известные ограничения

- `app/data/menu/en.json` пуст: при `BOT_LANGUAGE=en` используется русское меню.
- Прогнозирование не реализовано (остальные пункты меню — рабочие экраны).
- Yahoo Finance доступен не из всех регионов. При блокировке запросы либо
  завершаются таймаутом, либо получают ответ `429`, и бот сообщает о
  недоступности источника — данные при этом отдаются из кеша, пока он не
  устарел. Ответ `429` чаще всего снимается отпечатком браузера
  (`MARKET_IMPERSONATE`); если провайдер недоступен из региона — прокси в
  `MARKET_PROXY`.
- yfinance — неофициальная библиотека: Yahoo меняет ответы без предупреждения,
  поэтому пустые и неожиданные данные обрабатываются как штатная ситуация.
